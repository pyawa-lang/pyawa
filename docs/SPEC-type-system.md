## 2. 上游硬契约（由逐字同步 `Lib/` 导出，**非设计可改**）

`Lib/annotationlib.py`、`Lib/typing.py`、`Lib/dataclasses.py`、`Lib/functools.py` 都是纯 Python
且**禁止修改**，因此 3.14 的**注解协议是义务**（数值为 `Lib/` 内实测）：

| 事实 | 含义 |
|---|---|
| `Lib/annotationlib.py` 存在（**1,165 行**纯 Python） | PEP 649／749 的注解协议**必须**实现；`get_annotations()` 一类入口归它 |
| `typing.py`（**3,854 行**）引用 `__annotate__` **7 处**，并涉及 `__annotations__`／`__annotate_func__`／`__annotations_cache__` | 对象模型**必须**提供这四个名字；缺一则 `typing` 跑不起来 |
| `dataclasses.py` 引用 `__annotate__` **9 处**；`functools.py` **2 处** | 同上——注解不是"可选的类型系统功能"，而是**标准库的运行前提** |
| `inspect.py` 对 `__annotate__` **零引用** | 注解读取在 3.14 已下沉到 `annotationlib`；本文件不得假设 `inspect` 会代劳 |

> 结论：**注解表面属于语义级兼容的最低要求**，与"是否启用类型检查"无关。

## 3. 术语

- **标注**：`x: int`／`def f(x: int) -> int` 形式的既有 Python 语法。
- **已标注 / 未标注**：本编译单元内，某个参数／返回／变量是否带标注。
- **边界**：已标注代码与未标注代码的交界处（`BC-25`）。
- **相容关系**：渐进类型里替代类型相等的判定关系（具体规则见 `§13-9`）。
- **归责**：把一个边界失败判定为哪一方的责任。
- **安全档位**：一个程序（或编译单元）由标注覆盖率决定的严格程度。

## 4. 已定的框架（**不可动**）

- **TS-1** 类型系统是**渐进**的：**标注决定严格度**。未标注 ⇒ **不校验**；
  标注 ⇒ **编译期校验**。
- **TS-2** **完全不推断**：**禁止**为未标注的形参、返回或变量推断类型。
  `Any` 只能来自"未标注"或"显式写的 `Any`"，**禁止**由推断产生。
- **TS-3** 校验时机是**编译期**，且只作用于**已标注**的代码。
- **TS-4** 安全度是**程序级属性**：语言**禁止**强制标注，也**禁止**阻止标注。
  语言的义务是让**安全端真实成立**（`DESIGN.md` §6），而不是替程序选档位。
- **TS-5** 类型系统与**模式**的关系分三层，**禁止**混为一谈：
  - **标注**在**两种模式**下都**合法**，且**必须**按 3.14 的注解协议照常存储与读取（§2）。
    **禁止**因"不校验"而拒绝、剥离或忽略标注——`typing`／`dataclasses`／`functools`
    在 `.py` 文件里就依赖注解，剥离它们会**直接破坏"纯 Python 库逐字可用"**。
    一句话：**「不校验」不等于「不允许标注」**。
  - **校验**（编译期静态检查 ＋ 边界强制转换）**只在扩展模式**（`.pyawa`）启用；
    纯 Python 模式下的标注**不产生任何检查**。
  - **跨模式**调用是否被检查，由**被调用方**是否已标注决定：`.pyawa` 里已标注函数的序言含入参检查
    （`BC-23`／`BC-25`），故 `.py` 调用它时**也会**被检查并归责给 `.py` 调用方；
    反之 `.pyawa` 调用纯 `.py` 函数**不受检查**。
- **TS-6** **cast 深度是安全谱上的一档**（浅层／深层），**不是**降级 fallback；
  **禁止**把"检查得浅"当作默认而把"深"当特例（`DESIGN.md` §6）。

## 5. 两个必达性质

这两条不成立时，"可以选择安全"就是空话（`DESIGN.md` §6）。

- **TS-7** **渐进保证**：对同一语料**增删标注**，除类型错误外**行为必须不变**
  （Siek／Vitousek／Cimini／Boyland, *Refined Criteria for Gradual Typing*, 2015）。
- **TS-8** **边界归责**：全标注代码**不得**为源自未标注代码的错误背锅
  （Wadler／Findler, *Well-Typed Programs Can't Be Blamed*, 2009 的**负归责**）。
- **TS-9** 上述两条**必须**各有可执行验收（`T-TS-1`／`T-TS-2`），**禁止**只作声明。

## 6. 边界检查的语义（`BC-26` 的落点）

指令本体在 `SPEC-bytecode.md` §4.1；本节定**语义**。

- **TS-10** **入参**检查归责**调用方**（`CHECK_BOUNDARY_IN`）；**返回值**检查归责**被调用方**
  （`CHECK_BOUNDARY_OUT`）——方向与归责的对应**禁止**颠倒。
- **TS-11** 失败**必须**携带四要素：**方向**（入／出）、**期望类型**、**实际类型**、
  **边界位置**（文件名 ＋ 行号）（`BC-26`）。
- **TS-12** 归责异常的**具体类**未定（`§13-9`）：定案前**禁止**把任何具体异常类写成事实。
  但它**必须**让捕获方区分"是我传错了"与"是被调用方返回错了"（`TS-10`）。
- **TS-13** 检查**粒度**（是否深入容器、深入几层）未定（`§13-9`）：
  定案前**禁止**在规格里把某一粒度写成事实；实现若先选一个临时粒度，
  **必须**在代码与测试里显式标为**临时**并注明受 `§13-9` 制约。
- **TS-14** 开销上限未定（`§13-9`）。**禁止**以"开销可能高"为由默认关闭检查——
  那会把安全端变成不可达（`TS-4`）。

## 7. 相容关系与 `Any`（规则本身未定）

- **TS-15** 相容关系的**具体规则未定**（`§13-9`）。本文件只定它**必须**满足的性质：
  ① `Any` 与一切类型相容（否则未标注代码会被误报，`TS-1` 崩溃）；
  ② 规则**必须**使 `TS-7` 的渐进保证成立；
  ③ 规则**必须**可静态判定，**禁止**依赖运行时信息。
- **TS-16** `Any` 的**来源必须可枚举**（未标注、显式 `Any`，以及若定案允许的显式逃逸）；
  **禁止**出现"来源不明"的 `Any`——否则 `TS-7` 无法验证。

## 8. 槽位语义（`OM-11` 的八个）

`OM-11` 列出槽位、未给语义，`OM-15` 把它们推迟到本规格。以下为**语义契约**；
Rust 层签名依赖值的具体表示（`OM-38`），故签名本身列入 §14。

| 槽位 | 语义 | 省略时的默认行为 |
|---|---|---|
| `getattr` | 取属性；失败抛 `AttributeError` | 不支持属性访问 |
| `setattr` | 设属性；失败抛 `AttributeError`／`TypeError` | **只读** |
| `call` | 调用；失败抛 `TypeError`（含实参不匹配） | **不可调用** |
| `hash` | 返回哈希；**必须**与相等性一致 | 用对象身份 |
| `richcompare` | 六种比较；未支持的比较**必须**返回 `NotImplemented` | 用对象身份比较 |
| `iter` | 返回迭代器；失败抛 `TypeError` | **不可迭代** |
| `repr` | 调试表示 | 由类型对象给默认形式 |
| `str` | 字符串化 | 回退到 `repr` 的默认形式 |

- **TS-17** `richcompare` **必须**支持返回 `NotImplemented` 以触发反向比较——
  **禁止**用异常表达"不支持"。
- **TS-18** 任何槽位**禁止**在类型创建后改动（`Slots` 是不可变副本）。

---

## 9. 宿主 API 的类型通路

- **TS-19** 宿主的函数与类型**必须**在注册时提供签名（`AB-25`），
  且签名**必须**能生成 `.pyi`（`AB-28`）——**禁止**宿主 API 在类型系统里"无类型"。
- **TS-20** 宿主类型**必须**可被标注**命名**（`DESIGN.md` §8.3）；
  **禁止**要求用户用字符串或 `Any` 绕开。
- **TS-21** 宿主对象在**边界检查**下与普通类型**同等**对待（`TS-10`；表示层见 `OM-14`）。
- **TS-22** 宿主 API 的类型可见性**归签名机制**（`SPEC-c-abi.md` §9），
  本文件**禁止**另立一套宿主类型描述方式。

---

## 10. 安全档位与覆盖率

- **TS-23** 编译产物**必须**能给出「**标注覆盖率 ＋ 严格档位**」报告，
  供宿主决定是否加载该脚本（`DESIGN.md` §6 的产品含义）。
- **TS-24** 该报告**必须**由**编译期**信息算出；**禁止**依赖运行时统计（`TS-3`）。
- **TS-25** 报告的格式与档位命名**未定**，列入 §14——但"能给出"是本条的硬要求。

---

## 11. 工具链交付面与结构性局限

- **TS-26** LSP／类型检查器**必须**只覆盖**已标注**的代码，且**只在扩展模式**（`.pyawa`）下生效；
  **禁止**对外声称对未标注代码提供保证。
- **TS-27** **结构性局限必须如实说明**（`DESIGN.md` §6）：
  ① 因为完全不推断（`TS-2`），存量无标注代码**不受保护**，边界检查只补强"未标注 → 标注"这一方向；
  ② **纯 Python 模式的代码在任何配置下都不受校验**（`TS-5`）——但它的标注**照常保留且可读**。
  对外描述**禁止**省略这两点。

## 12. 验收（可测性质）

| 编号 | 测试 |
|---|---|
| `T-TS-1` | **渐进保证**：对同一语料增删标注，除类型错误外行为不变（`TS-7`） |
| `T-TS-2` | **归责方向**：标注函数被未标注代码以错类型调用 ⇒ 归责调用方；标注函数返回错类型 ⇒ 归责被调用方（`TS-10`） |
| `T-TS-3` | 未标注代码**不产生**类型错误（`TS-1`／`TS-2`） |
| `T-TS-4` | 归责信息含方向／期望类型／实际类型／位置四要素（`TS-11`） |
| `T-TS-5` | 覆盖率报告与源码中的标注一致（`TS-23`／`TS-24`） |
| `T-TS-6` | 宿主签名能生成 `.pyi` 且被类型检查器读到（`TS-19`） |
| `T-TS-7` | 两种模式下标注都保留且可读；**校验只在扩展模式发生**（`TS-5`） |
| `T-TS-8` | 未实现槽位的默认行为符合 §8 的表（`TS-17`／`TS-18`） |
| `T-TS-9` | `typing`／`dataclasses`／`functools` 在注解协议下可正常导入与使用（§2） |
