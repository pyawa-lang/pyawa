# Pyawa 需求备忘

> v1.1 · 2026-09 · 由需求澄清对话整理（含后续修正）
> 本文件是**决策记录**（记录"选了什么"）；技术设计见 `DESIGN.md`。

---

## 一句话定位

用 Rust 从零实现的、语义对标 **CPython 3.14** 的 Python 方言。核心是**像 Lua 一样易嵌入**：
宿主直接实现沙箱接口、脚本不可信且不可逃逸、纯 Python 库逐字可用。
此外提供**程序级可选的安全谱**（渐进类型，非强制）。目标**不是更快的 Python**。

Pyawa 本身不做数据/查询 DSL——它只负责"易嵌入"。具体 DSL 长什么样由下游宿主决定。

---

## 已确认的决策

| 维度 | 决策 |
|---|---|
| 定位 | 可嵌入脚本引擎（宿主可为 C/C++/Go/Java/Rust） |
| 下游用途 | 数据、科学计算、查询 DSL（由下游在 Pyawa 之上构建） |
| 兼容承诺 | 纯 Python 程序（不含 C 扩展）都能跑；**严格超集，只增不改** |
| 层次关系 | **Pyawa 是 Python 的一个方言（唯一）**；`.py` 与 `.pyawa` 是**同一方言内的两种模式**，**子集关系** `.py ⊂ .pyawa`，不是两个方言 |
| 扩展特性准入 | 每个新增特性必须**纯增量**——不得改变任何现有 Python 构造的语义；否则不得以"扩展"形式存在 |
| 单一实现 | **一份语法、一份语义规范、一套工具链**；模式只是编译参数，不存在两套文法/两套语义/两套工具 |
| 文件后缀与模式 | **后缀即模式开关**：`.py` ＝ 纯 Python 模式（CPython 3.14 语义，扩展语法一律报 `SyntaxError`）；`.pyawa` ＝ 扩展模式 |
| 模式作用域 | **逐编译单元**，不随 import 传染；`.py` 与 `.pyawa` 可共存同项目、互相导入 |
| 重名规则 | 忽略后缀后不得重名（`foo.py` 与 `foo.pyawa` 不能同处一个可导入位置）；项目级共存、模块级互斥 |
| 模式实现路径 | **不改 `Lib/`**：启动时向 `sys.path_hooks` 最前插入 `FileFinder` 子类 ＋ `.pyawa` loader；重名检查在 loader 内 |
| `.pyac` 命名与陈旧判定 | **文件名承载（模式, 指令集版本）＋ 头部承载源码指纹**：文件名不符即忽略（不读文件），匹配才比对指纹；**禁止**只依赖 mtime |
| 对标版本 | **CPython 3.14** |
| 兼容深度 | **语义级**：含元类、描述符、生成器帧、异常栈、`inspect`、import 副作用 |
| 执行模型 | 自有**字节码 + VM** |
| 内存管理 | **引用计数**（＋循环回收，因为 `gc` 模块属于语义） |
| 类型系统 | **渐进类型**：标注决定严格度，未标注＝不校验；**完全不推断** |
| 类型生效时机 | 编译期校验标注代码 |
| 类型生效范围 | **仅扩展模式**（`.pyawa`）：**校验**只在扩展模式启用；跨模式调用由**被调用方**是否已标注决定 |
| 标注的可用性 | **两种模式下都合法且必须保留**——按 3.14 注解协议存储与读取；「**不校验 ≠ 不允许标注**」 |
| 类型边界 | **边界强制转换 + 归责**（sound gradual typing） |
| 安全度归属 | **扩展模式程序**的**程序级属性**：由标注覆盖率决定；语言不强制也不阻止，责任是让"安全端"真实成立 |
| 相容关系 | **标准 consistency ＋ 子类型**：`Any` 双向相容；非 `Any` 按子类型判定；泛型参数按不变处理；**禁止**结构类型（协议）检查 |
| 归责异常 | **`TypeBoundaryError`**（**`TypeError` 的子类**）——既有 `except TypeError` 仍能兜住；携带方向／期望／实际／位置四要素 |
| 检查粒度 | **默认浅层**（类型标签级，不深入容器元素）；深层检查是**可选档位**，**禁止**默认开启 |
| 并发 | **先 GIL**；对象头预留无 GIL 结构；**不承诺 free-threading** |
| 核心差异化 | ① 可嵌入 / 可扩展（主线） ② **程序级可选的安全谱**（渐进类型：不强制，但标注即真实生效） |
| 性能 | **不是目标**（但启动延迟与常驻内存另议，见下） |
| 实现语言 | **Rust 从零实现** |
| 嵌入接口 | **仅稳定 C ABI**；只做嵌入，不做 C 扩展 |
| 嵌入硬需求 | 多实例隔离＋无全局状态、资源限额与可中断、宿主对象桥接、沙箱能力控制 |
| ABI 版本策略 | **尺寸 ＋ 追加式函数表**：三份契约共用一个版本号；末尾追加＝次版本，改语义／删符号＝主版本（旧宿主 `create` **必须**失败） |
| ABI 函数预算 | 公开函数 **≤ 120**；**核心层 `pa_`** 与**辅助层 `paL_`**，宿主可只实现核心层 |
| 脚本信任模型 | **脚本不可信、也不需要可信**；服务端运行；**不可逃逸**；VM 自治域与宿主控制面分离 |
| 沙箱模型 | **沙箱原生且强制**：能力层是唯一 I/O 出口；**权威在 provider，判定在 VM** |
| 沙箱接口归属 | 宿主**直接实现**沙箱所要求的接口——非配置项、无权限清单、无策略 schema；宿主的策略写在实现里 |
| 接口粒度 | 接口按**能力域**切分；宿主实现哪些域 ＝ 提供哪些能力；**未实现的槽位在调用时返回"未实现"错误** |
| 权限概念 | Pyawa **无权限语义**：只有"已实现/未实现"；拒绝由宿主在自己的实现里返回真实机器错误 |
| VM 平台观 | **无平台概念**：只认识能力接口。沙箱＝那层边界本身，不是可关闭的功能；真实机器实现下等效于无沙箱 |
| 独立运行时 | **自动注入真实机器实现**（同一接口的另一实现） |
| 兼容的条件性 | 独立运行时下"纯 Python 程序都能跑"无条件成立；嵌入时在**宿主已实现的域内**成立 |
| 能力调用模型 | **同步接口**；`asyncio` 保持用户态事件循环 + 生成器 |
| provider 形状 | **能力对象面** + VM 侧 POSIX 适配层（`fd` ＝ 实例内能力表索引） |
| provider 可替换粒度 | **按能力域**替换 |
| I/O 可中断 | **独立线程 + 取消令牌**；硬不变量：跨线程只传裸数据/OS 句柄 |
| 宿主对象表示 | **注册为真实类型**（方法表 + 属性，可被类型标注命名） |
| 宿主对象生命周期 | **引用计数交给脚本** + 宿主提供析构与 `traverse` 回调 |
| 宿主函数约定 | **栈式（Lua 风格）**——栈是 ABI 线格式 |
| 宿主 API 类型 | **声明签名 + 生成 `.pyi` 存根**——签名是类型元数据 |
| 标准库 | **`Lib/` 逐字同步上游、无须修改**（PSF-2.0 允许）；CI 用文件哈希校验差异 |
| Lib 例外清单 | **为空**：纯 Python 标准库 100% 逐字同步；字节码描述模块也由 C 层缝吸收 |
| Lib 本地修改 | **禁止**：bug 只能通过 C 层或上游修复，否则例外清单会长成第二个分叉 |
| C 兼容范围 | **不做 C-API/ABI**（不加载 C 扩展）；只保 C 模块的 **Python 层行为**；**数据格式不要求跨实现兼容**——编译产物是自有的 `.pyac` |
| 字节码产物 | **`.pyac`**（Pyawa 自有格式）；`.py` 与 `.pyawa` 的产物**都用这个后缀**，各自对应自己的源文件；与 CPython 的 `.pyc` **无关且不兼容** |
| `.pyac` 命名与失效 | ⚠ **待定**：命名方式与陈旧判定（判据：源文件重命名或模式改变后，旧产物不得被误命中） |
| C-API 概念模块 | `ctypes`/`_ctypes`/`_testcapi`/`_testbuffer`/`xxlimited*` 等走"未实现"路径，属实现缺口而非兼容破坏 |
| 对象模型自由度 | 因不做 C-API，对象头/类型对象/方法表**不受 `PyObject` 布局约束**，可完全自定 |
| 纯 Python 库保证 | **不改动、直接可用、效果完全一致**（自动成立：语言语义一致 ＋ C 模块 Python 层行为一致） |
| 实现观测面 | `sys.implementation`/`platform`/`sysconfig`/`dis`/`sys.getrefcount` 等**必然有差异**；`sys.implementation.name` **必须报 `pyawa`**，让库走自己的纯 Python 回退路径 |
| 生态边界 | 可用生态 ＝ **PyPI 上纯 Python 的那部分**；含 C 扩展的库需改写或不可用 |
| 包管理 | **推迟（不急）**：不自建安装器/resolver；`sys.path`/`site-packages`/`.pth` 语义由 `site.py` 逐字同步自动生效 |
| 错误兼容 | **结构兼容**：异常类型与层级一致，traceback 格式自定 |
| 工具链 | REPL、调试器/`sys.monitoring`、LSP/类型检查器、profiler |
| 兼容性验收 | 暂不定 |
| 项目节奏 | 探索阶段，暂不谈交付 |
| 当前里程碑 | **M0 设计文档** |

## 决策的必然后果

这些不是新决策，而是上面那些选择的数学后果。写下来是为了避免以后反复。

1. **`gc` 模块进入语义范围。** 选了"引用计数＋语义级兼容"，则 `gc.collect()`、`gc.get_objects()`、
   `weakref`、`__del__` 的触发时机都属于必须实现的语义。单纯 refcount 不够，**必须有循环回收器**。

2. **对象头必须自己设计，但不复刻 `PyObject`。** Rust 的 `Rc` 不可用：它处理不了循环，
   也不提供 Python 层要求的引用计数可观测性（`sys.getrefcount`、`id()`、immortal 对象等）。
   布局则可以完全按 Pyawa 自己的设计来（见"对象模型自由度"行）。

3. **"完全不推断"是"`Lib/` 逐字同步"的必要配套。** `Lib/` 中绝大多数代码没有类型标注；
   一旦做全程序推断，兼容性会被误报淹没。两个决策互为前提。

4. **只做自有嵌入 C ABI ⇒ 值必须能以不透明句柄跨 ABI 传递。** 但这**不等于**要长得像
   `PyObject`：CPython 的 C-API/ABI 不在范围内（见"C 兼容范围"行），对象模型完全自定。
   约束只有三条：Rust panic **绝不允许跨 FFI 边界**（每个入口 `catch_unwind`）；
   公开接口不出现泛型/单态化；"稳定"是对未来的承诺，因此 ABI 版本策略必须在第一个公开版本定死。

5. **多实例隔离＋无全局状态 ⇒ 运行时状态必须挂在实例上**（类似 `lua_State`）。
   实现上意味着：Rust 的 `static mut` / 全局可变状态基本禁用，`thread_local` 也要极少化。
   这一条是**架构绑定**的，做不到就永远补不回来。

6. **沙箱是架构而非模式。** 因为不存在未注入的 I/O，所以沙箱**没有绕过路径**；
   又因为宿主**必须实现**它想提供的域，所以"没实现"就是没提供（调用时报"未实现"）。
   但这**不等于默认安全**：若宿主的实现就是真实机器，`os.system("rm -rf /")` 照跑——
   **等效于没有沙箱，但沙箱客观存在**。这两句话必须分开对外说。

7. **能力层就是 CPython 的 C 模块边界。** CPython 自身就是"纯 Python 包装层 + C 内核"
   （`os.py`→`posix`、`io.py`→`_io`、`socket.py`→`_socket`）。依赖倒置与 `Lib/` 同步是同一件事。

8. **`sys.monitoring` 与 profiler 是 VM 架构约束**，不是后加功能：事件点必须在主循环里预留。

9. **"渐进"是核心机制，不是"可选功能"。** 安全度是程序级属性：程序通过标注覆盖率选择自己的安全档位。
   语言的义务不是强制安全，而是让**安全端真实成立**——即必须满足**渐进保证**（增删标注不改变行为）
   与**边界归责**（全标注代码不为未标注代码的错误背锅）。这两条不成立时，"可以选择安全"是空话。
   因此类型系统的设计问题**必须被回答，只是排序靠后**，不能因为"非强制"而砍掉。

10. **`Lib/` 逐字同步 ⇒ 三条不变量都可 CI 强制**：无全局可变状态、VM 核心无平台依赖、
    `Lib/` 与上游哈希零差异。它们都是"会红会绿"的性质，不靠纪律维持。
