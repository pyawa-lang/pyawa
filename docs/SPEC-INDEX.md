## 2. ID 与引用规则

- **每个文件独占自己的前缀**，编号一经分配**不得复用**；作废写 `~~OM-12~~` 并保留空号。
- 引用他文件的约束**只写编号**，**禁止**重述其内容。例：
  "帧的每个栈项**必须**持有引用（`OM-16`／`OM-17`）" ✅
  "帧的栈项增加引用计数，decref 时……" ❌（这是重述，会产生第二个真相源）
- 引用尚未写出的文件时，用**临时假设**并显式标注：
  `（依赖 TS-3，未定；本文件暂假设边界检查不引入新指令）`

## 3. 依赖的性质（决定能否并行）

- **引用依赖**（可并行）：只需知道对方存在某个编号，不需要对方先写。
  例：字节码引用对象模型的 `OM-`；C 模块引用能力域的 `CP-`。
- **真依赖**（不能并行）：一个决定同时属于两份文档，谁写都会替对方做主。
  全文档集只有 **3 处**，见 §4。

### 4.1 已决：边界检查的落点 ＝ 方案 B（专用指令）

## 5. 每份规格必须包含的固定小节

为了可独立评审，每份规格**必须**有：

1. **范围与依赖**——本文件规定什么、不规定什么（指向别处）、依赖谁
2. **上游硬契约**（若有）——由 `Lib/` 逐字同步导出、非设计可改的义务
3. **硬约束**——编号，可被测试引用
4. **验收**——可测性质，逐条引用编号
5. **未决**——引用 `DESIGN.md` §13 的编号，**禁止**在本文件里私自决定
6. **尚未写出**——本规格自己缺哪些节／哪些表；**没有缺口也必须显式写"无"**

### 5.1 「未决」与「待写小节」是两件事

混为一谈会让 `v0` 失去含义，也会漏节——`SPEC-bytecode.md` 就曾把"指令集本体未写"漏在未决清单之外。

| | 未决 | 待写小节 |
|---|---|---|
| 含义 | **决策**还没拍板 | **内容**还没写 |
| 归属 | `DESIGN.md` §13（唯一归口），本规格只引用编号 | **本规格自己** |
| 可否私自定 | **禁止**（第 5 条） | 必须写，且**必须**在第 6 条里列出 |
| 状态表现 | `DESIGN.md` §13 的一个编号 | 本文件里的一行清单 |

- **禁止**把"某节还没写"写成"未决"——那会让读者以为在等人拍板
- **禁止**把"某决策还没定"写成"待写"——那会让人以为只是没写
- `v0` 的含义是：**未决已全部归口到 §13，而已知缺口已在第 6 条列全**——不是"写了一些"

## 6. 独立开写的三条前提

满足这三条即可任意顺序、任意份数并行：

1. **只引用编号，不重述内容**（§2）
2. **遇到他文件的未决项，写临时假设并标注**，不要替对方决定（§3）
3. **真依赖按 §4 的唯一归属执行**；§4.1 已决（方案 B），按 §4.1 执行

### 7.5 与"缺口"的分界

**缺口 ＝ 规格自己说"我缺这一节"**——即各规格末尾「尚未写出」节里列出的条目（`CX-17` 要求
每份已写规格都必须有该节）。**本节 7.1–7.4 四类都不是缺口。**

当前**真正声明的缺口只有两处**：`SPEC-bytecode.md` 的"超出 §10 的指令"、
`SPEC-c-modules.md` 的"逐模块合约表"。其余各规格的「尚未写出」节均自报"无未写小节"。
