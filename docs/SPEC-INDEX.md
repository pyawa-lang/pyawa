## 2. ID 与引用规则

- **每个文件独占自己的前缀**，编号一经分配**不得复用**；作废写 `~~OM-12~~` 并保留空号。
- 引用他文件的约束**只写编号**，**禁止**重述其内容。例：
  "帧的每个栈项**必须**持有引用（`OM-16`／`OM-17`）" ✅
  "帧的栈项增加引用计数，decref 时……" ❌（这是重述，会产生第二个真相源）
- 引用尚未写出的文件时，用**临时假设**并显式标注：
  `（依赖 TS-3，未定；本文件暂假设边界检查不引入新指令）`

## 3. 依赖的性质（决定能否并行）

- **引用依赖**（可并行）：只需知道对方存在某个编号，不需要对方先写。
  例：字节码引用对象模型的 `OM-`；C 模块引用能力域的 `CP-`。
- **真依赖**（不能并行）：一个决定同时属于两份文档，谁写都会替对方做主。
  全文档集只有 **3 处**，见 §4。

## 4. 三处真依赖的归属（写死，消除争用）

| 交叉点 | **唯一归属** | 其他文件怎么写 |

### 4.1 已决：边界检查的落点 ＝ 方案 B（专用指令）

`DESIGN.md` §13-9 已拍板：**专用检查指令**（`CHECK_BOUNDARY_IN`／`CHECK_BOUNDARY_OUT`）。

- **归属 `SPEC-bytecode.md`**（`BC-23`…`BC-29`），字节码规格已按此写入。
- `SPEC-type-system.md` **只引用** `BC-23`…`BC-26`，**禁止**自行定义指令；
  但它仍拥有"检查什么、相容关系如何、归责异常的具体形态"（`BC-26` 指向它）。
- **连带义务**：指令集必须有版本常量，且 **`.pyac` 头部必须携带它**（`BC-29`）。
  来源由字节码规格提供，落地在第 3 份规格。

因此 **9 份可全部并行开写**。唯一的顺序约束是措辞性的：类型系统引用 `BC-26` 时以
"依赖 `BC-26`"标注即可，不必等字节码规格写完。

## 5. 每份规格必须包含的固定小节

为了可独立评审，每份规格**必须**有：

1. **范围与依赖**——本文件规定什么、不规定什么（指向别处）、依赖谁
2. **上游硬契约**（若有）——由 `Lib/` 逐字同步导出、非设计可改的义务
3. **硬约束**——编号，可被测试引用
4. **验收**——可测性质，逐条引用编号
5. **未决**——引用 `DESIGN.md` §13 的编号，**禁止**在本文件里私自决定

---

## 6. 独立开写的三条前提

满足这三条即可任意顺序、任意份数并行：

1. **只引用编号，不重述内容**（§2）
2. **遇到他文件的未决项，写临时假设并标注**，不要替对方决定（§3）
3. **真依赖按 §4 的唯一归属执行**；§4.1 已决（方案 B），按 §4.1 执行
