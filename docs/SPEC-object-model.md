## 1. 范围

本文件规定 Pyawa 运行时的对象模型：实例级内存、对象头、类型对象、引用计数协议、
循环回收、弱引用、宿主对象。

## 2. 依据（本规格由这些决策推导，不自行发明）

| 依据 | 对本文件的约束 |
|---|---|
| 引用计数 ＋ `gc` 属于语义（R-内存管理） | 必须有循环回收器，且 `gc` 的可见行为要对齐 |
| 对象模型完全自定（R-对象模型自由度） | **不复刻 `PyObject` 布局**；头部字段由本文件定 |
| 不做 C-API（R-C 兼容范围） | 头部**不跨 ABI**，只作内部表示 ⇒ 可自由演进 |
| 多实例隔离 ＋ 无全局可变状态（R-嵌入硬需求、后果 5） | 对象状态必须挂在实例上；禁止进程级全局对象 |
| VM 无平台概念（DESIGN §7 原则 5） | 对象层禁止依赖 OS 与 libc |
| 宿主对象注册为真实类型；refcount 交给脚本；须提供 `traverse`（R-宿主对象表示/生命周期） | 宿主对象走同一类型系统与回收器 |
| 脚本不可信、资源限额由 VM 记账（DESIGN §7 原则 1／3） | 内存记账在 VM 侧，能力接口不承担预算 |
| 启动延迟与常驻内存可能列为产品指标（DESIGN §13-17） | 头部不得无节制膨胀；**先正确后紧凑** |

## 3. 术语

- **对象**：带头部、有类型、可被引用的内存块。
- **类型对象**：一种特殊对象，描述实例的行为与布局。
- **实例（State）**：一次嵌入所创建的全部运行时状态的宿主，类似 `lua_State`。
- **持有引用**：调用方对某对象拥有一个引用计数。
- **借用引用**：不增加计数的临时访问权，仅在"持有者存活"的窗口内有效。
- **可成环对象**：能直接或间接引用其他对象的对象（容器、实例、帧等）。

## 4. 实例级内存（本文件其余部分都建立在这一节上）

- **OM-1** 每个实例**必须**拥有独立的对象堆；**禁止**对象跨实例共享。
  （连 `None`／小整数这样的单例也按实例划分——见 OM-18。）
- **OM-2** 实例销毁**必须**释放其堆内全部内存，**无论循环是否被回收过**。
  即：销毁实例不得依赖回收器先跑完。
- **OM-3** 内存记账**必须**在 VM 侧按实例进行（每实例字节计数器）。
  **禁止**把预算职责下放给能力接口——能力接口只提供"权威"，判定与记账在 VM（DESIGN §7 原则 1）。
- **OM-4** 分配器**必须**可参数化为实例私有（建议：实例私有 arena，后端可用系统分配器）。
  **禁止**使用进程级可变分配状态。

> 这三条合起来给了三个直接好处，也是它们存在的理由：**真隔离**、**O(1) 级联销毁**、
> **内存限额可实施**。代价是对象不能共享，接受。

## 5. 对象头

- **OM-5** 所有对象**必须**以同一头部开头（M1 阶段统一，不做拆分）。
  ```rust
  #[repr(C)]
  pub struct Header {
      pub refcount: Cell<u32>,          // 非原子：由"先 GIL"决策决定
      pub flags: Cell<u32>,             // 保留 32 位宽度，便于将来换原子类型
      pub ty: NonNull<Type>,            // 类型对象指针
      pub gc_prev: Cell<*mut Header>,   // 循环回收链表（仅 GC_TRACKED 有意义）
      pub gc_next: Cell<*mut Header>,
  }
  ```
- **OM-6** 头部**禁止**出现在任何 C ABI 签名里；宿主只见**不透明句柄**。
  因此头部布局**可以**在后续版本自由演进；`#[repr(C)]` 与 `flags` 的 32 位宽度
  只是为了给"将来可能无 GIL"留门，**不是** ABI 承诺。
- **OM-7** `flags` 位分配（其余保留，禁止他用）：

  | 位 | 名称 | 含义 |
  |---|---|---|
  | 0 | `IMMORTAL` | 计数不增减（语义待定，见 §13-5） |
  | 1 | `GC_TRACKED` | 参与循环回收 |
  | 2 | `HAS_WEAKREFS` | 存在弱引用 |
  | 3 | `FINALIZING` | 正在执行 `__del__`，用于防重入 |
  | 4–7 | 预留（无 GIL 所需） | **禁止**占用 |
  | 8–31 | 类型相关 | 由类型对象自行定义 |

- **OM-8** M1 **必须**用统一头部，**禁止**提前做"仅容器带 gc 链"的拆分优化。
  理由：头部不跨 ABI（OM-6），可后改；循环回收的正确性优先于每对象几字节。
  拆分与否**必须**在测出常驻内存后按数据决定（时机取决于 §13-17，取舍本身见 §13-19）。

## 6. 类型对象

- **OM-9** 类型对象**必须**自身也是对象（有 OM-5 头部）。
- **OM-10** 类型对象**必须**至少包含：名字、基类数组、MRO、标志、槽位表、类型字典。
- **OM-11** 槽位表**必须**至少含以下能力（Rust 函数指针，语义等价于 CPython 的 `tp_*`，
  但**命名与布局自定**）：
  `dealloc`、`finalize`、`traverse`、`clear`、`getattr`、`setattr`、`call`、`hash`、
  `richcompare`、`iter`、`repr`、`str`。
  `finalize` 承载 **OM-20** ① 的终结器（`__del__`，可复活）——原清单遗漏了它，此处补入。
- **OM-12** **可成环的类型必须**标记 `GC_TRACKED`，并**必须**提供 `traverse` 与 `clear`。
- **OM-13** MRO **必须**用 C3 线性化（语义级兼容要求，`super()` 依赖它）。
  **宿主类型参与 MRO**（`§13-1` 已决为**允许继承**）：宿主类型**必须**有 `tp_bases`／`__mro__`，
  且类创建钩子（`__init_subclass__`／`__set_name__`）在基类为宿主类型时**必须**照常工作。
- **OM-14** 宿主类型（DESIGN §8.3）**必须**注册进同一结构；宿主**必须**提供 `dealloc` 与
  `traverse`，并声明签名元数据。**禁止**为宿主类型另立一套对象表示。
  **可被脚本继承**（`§13-1` 已决）：宿主类型**必须**提供**子类分派槽位**——`tp_new`／`tp_dealloc`／
  `tp_traverse` 得能被 Python 子类**覆写**；且子类实例**必须**能携带**实例字典**
  （宿主对象布局是固定的，故字典**必须**另行挂载，并在 `OM-11` 的 `getattr`／`setattr` 槽位上生效）。
- **OM-15** 类型对象的创建**禁止**依赖全局可变注册表；类型注册表按实例存放。

## 7. 引用计数协议

- **OM-16** 所有权约定：**所有函数返回值为"新引用"**；需要借用语义时**必须**在签名中显式标注
  （例如返回 `Borrowed<T>`）。**禁止**隐式借用返回值。
- **OM-17** Rust 侧持有引用**必须**经 RAII 守卫（如 `Owned<T>`／`PyRef<T>`）；
  **禁止**在业务代码里裸写 incref／decref。守卫在 `Drop` 中 decref。
- **OM-18** **禁止**使用 `Rc`／`Arc` 作为对象引用（处理不了循环，且不提供可观测计数）。
- **OM-19** 借用引用的有效窗口：**禁止**跨任何"可能触发 decref 的调用"保存借用引用
  （包括属性访问、比较、迭代、任何可调用对象的调用）。编译器／类型系统**应当**用生命周期
  表达这条约束，而不是靠注释。
- **OM-20** decref 归零后的释放顺序**必须**是：
  ① 若类型有终结器，置 `FINALIZING` 并调用 `__del__`；
  ② 清空容器持有的引用（`clear`）；
  ③ 释放内存。
  若 ① 期间对象被复活（计数回升），**必须**清除 `FINALIZING` 并**放弃**释放。
- **OM-21** 容器清空**必须**避免深递归：使用显式待处理栈（或自底向上清空）。
  **禁止**用朴素递归——深链表会打爆 C 栈，而脚本不可信（DESIGN §7 原则 3）。
- **OM-22** `sys.getrefcount` 返回计数加一（借用参数的那一份），与 CPython 的可见语义一致。

### 7.1 载荷存储：OM-17 的唯一例外（`OM-40`）

`Owned`／`PyRef` 守卫绑定在 `&Instance` 上（生命周期形式），因此**存不进对象载荷**。
裁决：**头部不加 owner 指针**，改由调用方**线程式传入**实例（与已落地的槽位签名一致——
`clear`／`finalize` 已经收 `&Instance`）。

- **OM-40** 对象载荷中存储的子引用**必须**是裸 `NonNull<Header>`，且**只能**在
  `clear`／`traverse`／`dealloc` 三个槽位内释放——它们都从调用方收到 `&Instance`。
  **除此之外禁止释放载荷中的引用**；**OM-17** 仍是默认规则，本条是它唯一的例外。

连带约束：

- 头部**不含**实例指针 ⇒ 对象**不能自我释放**，释放一律经 `Instance`
- **禁止**要求 `Instance` 地址稳定（这是选择本方案而非"头部加 owner"的主要收益）
- 载荷**禁止**含持有子引用的 Rust `Drop`：`dealloc` 释放载荷时**不得**间接触发子对象的 decref
- 需要访问子对象时，**必须**用 `Instance` 上的访问器现取守卫，用完即还

> 代价：载荷代码比"头部带 owner"更容易写错。`clear`／`traverse`／`dealloc` 三处的实现
> **必须**逐条对照 **OM-40** 复核。

## 8. 单例与 immortal

- **OM-23** `None`／`True`／`False`／小整数／空串等单例**必须**按实例创建，
  **禁止**做成进程级全局（违反"无全局可变状态"）。
  **小整数区间的参照值（本机 3.14.4 实测）**：**`-5..=256`**——以 `make(x) is make(x)` 的**拐点**测定；
  **禁止**用字面量 `x is x` 探测（常量共享会给出假象，实测时第一次就踩了这个坑）。
  该区间**不是实现自由**：`is` 可观测，故**必须**与参照实现一致。
  ⚠ 单例的**引用计数**行为受 `DESIGN.md` §13-5（immortal 与 `getrefcount` 对齐）约束；
  定案前**禁止**把任何具体 refcount 值当成契约（`OM-24` 的 `IMMORTAL` 位同理）。
- **OM-24** `IMMORTAL` 位（OM-7 bit 0）M1 **只需预留并保持 0**。
  **immortal 策略已决（§13-5）：不实现**——`sys.getrefcount` 返回**真实计数**；
  单例与 interned 字符串的 refcount **必须**登记进 `MS-19` 差异清单（它们属"实现观测面"，
  参照实现的值依赖其内部引用数），`T-OM-1` 只比对**普通对象**。
  实现**禁止**依赖该位做正确性判断。

## 9. 循环回收

- **OM-25** 算法：**标记-清除**，作用域限于 `GC_TRACKED` 对象。M1 单代，按分配计数阈值触发。
  对象头**不拆**"容器专属 gc 链"（`§13-19` 已决为**推迟**）：**M1–M4 保持单链**；是否拆由
  **常驻内存实测**驱动；它是纯内部布局（`OM-6`，不进 ABI），故后加**不破坏兼容**。
- **OM-26** 触发点：分配计数达阈值（自动）、`gc.collect()`（显式）。阈值参数**必须**可配置。
  **参照实现的形态与取值（本机 3.14.4 实测）**：`gc.get_threshold() == (2000, 10, 0)`。
  `set_threshold(t0, t1, t2)` **必须**照抄**三元组**形状；内部**单代**、**只有 t0 生效**，
  后两位**存而不生效**（这一"存而不生效"**必须**标为**临时**，等真分代落地）。
  **禁止**改成单参数形态——纯 Python 层会解三元组（`§13-18` 已决）。
- **OM-27** 回收顺序**必须**为：① 求不可达集合 → ② **先清弱引用** → ③ 调终结器 `__del__`
  → ④ 释放。顺序**禁止**改动：这是 PEP 442 语义，弱引用回调看得到"对象已死但尚未终结"的状态。
- **OM-28** `gc` 模块的**可见行为属于语义**，至少实现：
  `collect`、`get_objects`、`get_referrers`、`get_referents`、`is_tracked`、
  `garbage`、`enable`／`disable`／`isenabled`、`threshold`、`freeze`，
  以及 **`get_threshold`／`set_threshold`／`get_count`／`get_stats`**（`§13-18` 已决：**在范围内**；
  `get_count()` 按单代**如实**返回 `(n, 0, 0)` 形状，差异登记进 `MS-19`）。
- **OM-29** `get_referrers`／`get_referents` 依赖遍历 ⇒ **这正是宿主对象必须提供 `traverse` 的原因**
  （OM-14）。二者不得以"查不到宿主对象"方式降级。
- **OM-30** **禁止**把不可达但尚未回收的对象暴露给脚本。

## 10. 弱引用

- **OM-31** 弱引用**禁止**增加引用计数。
- **OM-32** 对象进入死亡流程时**必须**先清空其弱引用并触发回调（顺序见 OM-27）。
- **OM-33** 弱引用回调抛出的异常**必须**被吞掉并报告，**禁止**传播到触发回收的调用点。

---

## 11. 宿主对象

- **OM-34** 表示：不透明指针 ＋ 宿主提供的 `dealloc`／`traverse`；脚本侧呈现为**真实类型**（OM-14）。
- **OM-35** 引用计数归属：**脚本侧计数**，宿主交出所有权（DESIGN §8.3）。
- **OM-36** `traverse` **必须**列出该对象直接引用的**全部**脚本对象：
  漏报 ⇒ 永久泄漏；虚报 ⇒ 误回收。二者都是缺陷。
- **OM-37** 宿主对象／方法的暴露**必须**走与能力层**同一套授权模型**（DESIGN §8.3）；
  桥接**禁止**成为绕过能力接口的旁路。

---

## 12. 值的内部表示（建议，非 ABI 可见）

- **OM-38** 值的内部表示**不跨 ABI**，实现可自选；**建议** M1 用带标签的枚举
  （判别式 ＋ 载荷），**不建议** M1 就做 NaN-boxing。
  理由：NaN-boxing 是性能优化，而性能不是目标；先换取正确性与可调试性。
- **OM-39** 任何值表示的选择**必须**满足：小整数与单例的内联不改变语义（`is` 语义按 OM-23 的单例表）。

## 13. 验收（可测性质）

| 编号 | 测试 |
|---|---|
| T-OM-1 | 固定脚本集上 `sys.getrefcount` 的返回值与 CPython 一致（受 §13-5 影响，见 §14） |
| T-OM-2 | 构造已知环 → `gc.collect()` → 对象被释放且 `__del__` 恰好调用一次 |
| T-OM-3 | 环中对象的弱引用被清空，且回调恰好触发一次、且早于终结器 |
| T-OM-4 | 两个实例的对象互不可见；销毁任一实例后无残留（含环） |
| T-OM-5 | 深链表（≥ 1e6 节点）被回收时不发生栈溢出（对应 OM-21） |
| T-OM-6 | 宿主对象参与环：漏报 `traverse` 的测试实现**应当**能被 `gc` 检出并报错 |
| T-OM-7 | CI 静态检查：禁止 `static mut`／`thread_local`（`CX-3`；`OM-1`、`OM-4`） |
| T-OM-8 | CI 静态检查：VM 核心 crate 无平台依赖（`CX-4`） |
| T-OM-9 | 容器载荷按 `OM-40` 释放：构造容器 → 释放 → 子对象计数正确归零；且除 `clear` 外无释放路径（`OM-40`） |
