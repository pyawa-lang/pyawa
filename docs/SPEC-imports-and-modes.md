## 2. 上游硬契约（由逐字同步 `Lib/` 导出，**非设计可改**）

`Lib/importlib/_bootstrap.py`、`Lib/importlib/_bootstrap_external.py`、`Lib/site.py` 都是纯 Python
且**禁止修改**，因此下列事实是义务而非选择（数值为 `Lib/` 内实测）：

| 事实 | 位置 | 对 Pyawa 的含义 |
|---|---|---|
| 默认文件查找钩子是**追加**的：`sys.path_hooks.extend([FileFinder.path_hook(*supported_loaders)])` | `_bootstrap_external.py:1560–1561` | Pyawa **可以**用 `insert(0, …)` 抢先（`zipimport` 已用同一手法） |
| `SOURCE_SUFFIXES = ['.py']` | `_bootstrap_external.py:229` | 扩展名**不得**靠改它来加；必须由 Pyawa 自己的 finder 提供 |
| `FileFinder.path_hook(*loader_details)` 是类方法工厂 | `_bootstrap_external.py:1440` | Pyawa 的 finder 可以继承 `FileFinder` 并复用该工厂 |
| 该模块第 30 行 `import marshal` | `_bootstrap_external.py:30` | `marshal` **必须**存在（`SPEC-object-model.md` 已定其义务） |
| `site.py` 负责 `sys.path`、site-packages、`.pth` | `Lib/site.py` | Pyawa **禁止**另立一套路径逻辑（见 `IM-22`） |

## 3. 术语

- **模式**：编译与运行一个编译单元时启用的特性级别。共两种：**纯 Python 模式**与**扩展模式**。
- **重名**：同一可导入位置内，两个源文件去掉**最后一个**后缀后基名相同。
- **可导入位置**：`sys.path` 上的一个目录（或包目录）。
- **`.pyac`**：Pyawa 的字节码产物（自有格式，与 CPython 的 `.pyc` 无关）。
- **引导模块**：`importlib._bootstrap`／`_bootstrap_external` 等启动路径上的模块。

---

## 4. 模式开关

- **IM-1** 模式**必须**由源文件后缀决定：`.py` → 纯 Python 模式；`.pyawa` → 扩展模式。
- **IM-2** 模式是**逐编译单元**的属性，**禁止**随 import 传染：`.py` 导入 `.pyawa` 时，
  被导入者仍按**它自己的后缀**取模式（`DESIGN.md` §2.1）。
- **IM-3** 纯 Python 模式下扩展语法**必须**报 `SyntaxError`（`BC-15`）——这是 `.py` 纯净性的落地点。
- **IM-4** 没有后缀的来源（`-c`、stdin、字符串、REPL）的模式由 **§13-13** 定；
  定案前**必须**由调用方显式传入，**禁止**猜测或取"全局默认"。
- **IM-5** 模式**必须**作为编译器的显式参数传入（`BC-14`）；**禁止**从环境变量、
  全局状态或文件内容推断。
- **IM-6** `.py` 与 `.pyawa` 是**同一个方言内的两种模式**（`DESIGN.md` §2.1），
  二者**必须**共用同一份语法与语义规范——**禁止**出现两套文法或两套求值规则。

---

## 5. 重名规则

- **IM-7** 同一可导入位置内，**禁止**存在重名的两个源文件（`foo.py` 与 `foo.pyawa`）。
- **IM-8** 重名检测**必须**发生在 **import 时**，且**必须**在任一方被加载**之前**——
  **禁止**只靠外部工具或 linter。
- **IM-9** 判定规则：去掉**最后一个**后缀后的基名相同即重名；对包而言 `__init__.py` 与
  `__init__.pyawa` 同理（是否允许后者见 `§13-14`）。
- **IM-10** 重名**必须**以 `ImportError` 的**子类**报出——`except ImportError` 仍须能捕获，
  且错误消息**必须**点明两个冲突文件的具体路径。

> 重名是 **Pyawa 独有的情形**（CPython 会直接忽略 `.pyawa`），因此它不属于"两种失败"的
> 任何一类（`DESIGN.md` §2 的"未实现"与"已实现但拒绝"），而是一个新错误——故必须清晰可辨。

## 6. import 钩子的装配

- **IM-11** Pyawa 的 finder **必须**用 `sys.path_hooks.insert(0, …)` 装配，抢在 §2 表格中
  被**追加**的默认钩子之前。
- **IM-12** **禁止**修改 `Lib/`，包括 `SOURCE_SUFFIXES`（`DESIGN.md` §9、`CX-8`）；
  扩展名**必须**由 Pyawa 自己的 finder 提供。
- **IM-13** Pyawa 的 finder 对 `.py` 的处理**必须**与上游 `FileFinder` 语义等价
  （建议直接继承并复用其工厂，见 §2）——否则 `Lib/` 与第三方纯 Python 包的解析会变。
- **IM-14** `Lib/` 全是 `.py` ⇒ 一律纯 Python 模式；**禁止**为 `Lib/` 引入扩展模式。
- **IM-15** import 的**全部 I/O 必须**经能力层（`DESIGN.md` §7 原则 1）：
  路径解析、读源文件、读缓存、写缓存都走 `fs` 域（`CP-21`／`CP-22`）。
  **禁止**直连真实文件系统。
- **IM-16** 只读根能力下 import **必须**优雅降级为**不写缓存**：不得报错，也不得回退到真实机器。
- **IM-17** CPython 生成的 `__pycache__/*.pyc` **必须**被忽略（不读不写）；
  **只**发 `.pyc` 而不带 `.py` 的包**不支持**（`DESIGN.md` §9）。

- **IM-30** **finder 落在 Python 层**：它**必须**继承 `_bootstrap_external.FileFinder` 并复用
  其 `path_hook` 工厂（§2），**禁止**在 Rust 侧另写一套目录扫描——否则 `Lib/` 与第三方包的
  解析语义会漂移。finder 只做"识别后缀 ＋ 选 loader"。
- **IM-31** **loader 的编译与 `.pyac` 读写落在 Rust 层**，且**必须**经能力层（`IM-15`）；
  Python 层的 loader **禁止**自己 `open()`。两层交界**必须**是 `SPEC-c-abi.md` 的函数面，
  **禁止**另开私有 FFI。
- **IM-32** 重名检测（`IM-7`…`IM-10`）**必须**在 Python 层 finder 内完成——它需要枚举同目录的
  两种后缀；结果**必须**以 `ImportError` 子类报出（`IM-10`）。

## 7. `.pyac`

- **IM-18** `.pyac` 是 Pyawa 的**自有**产物，与 CPython 的 `.pyc` **无关且不兼容**（`DESIGN.md` §2.1）。
  **产物路径**：`<pkgdir>/__pyawa__/<源文件名>.<指令集版本>.pyac`
  ——例：`foo.py` → `__pyawa__/foo.py.1.pyac`；`foo.pyawa` → `__pyawa__/foo.pyawa.1.pyac`。
  **模式体现在源文件名里**，故重命名或改模式**必然**换名（见 `IM-20`）。
- **IM-19** 头部字段顺序**必须**为：`magic` ＋ **指令集版本**（`BC-29`）＋ 模式 ＋ 优化级 ＋
  源码长度 ＋ 源码指纹 ＋ 代码段偏移与长度。头部**不进 ABI**（`OM-6`）。
- **IM-20** **陈旧判定必须两步**，且**必须**按此顺序：
  ① **文件名不匹配**（模式或指令集版本）⇒ **直接忽略，连文件都不读**；
  ② 名字匹配 ⇒ 读头部比对**源码指纹**（长度相同而哈希不同 ⇒ 陈旧）。
  **禁止**只依赖 mtime。
- **IM-21** 产物**必须**只由「源码 ＋ 模式 ＋ 优化级别 ＋ 指令集版本」决定
  （`BC-16` 的纯函数性）；**禁止**依赖绝对路径、mtime 或注册顺序。
- ~~IM-22~~ **作废**：其内容（"命名与格式方案未定"）随 `§13-15` 裁决失效；编号保留，不重用。
- **IM-23** `importlib.util.cache_from_source`／`source_from_cache` 的往返**不承诺**
  （自有格式，`SPEC-object-model.md` §9）。

## 8. `site` 与 `sys.path`

- **IM-24** `sys.path` 构建、site-packages 扫描、`.pth` 处理**归 `site.py`**（逐字同步）；
  Pyawa **禁止**另立路径逻辑或额外的 site 钩子。
- **IM-25** 包管理**不做**（`REQUIREMENTS.md`：推迟）：Pyawa 不提供安装器与 resolver；
  只保证"能 import 外部已装好的纯 Python 包"。
- **IM-26** `site.py` 的执行不得因 Pyawa 特有原因被跳过——跳过它会破坏 `IM-24` 的语义。

---

## 9. 引导模块的冻结

- **IM-27** `importlib._bootstrap`／`_bootstrap_external` 等引导模块**可以**冻结（frozen）；
  冻结是**构建步骤**，**不改** `Lib/` 源文件（`IM-12` 仍成立）。
- **IM-28** 冻结的字节码**必须**由 Pyawa 自己的编译器产出，并受 `BC-29` 的指令集版本约束；
  指令集升版本时冻结产物**必须**同步重建。
- **IM-29** 冻结路径与非冻结路径的行为**必须**一致（同一源码、同一模式 ⇒ 同一语义）。

---

- **IM-33** 冻结**必须**是**构建步骤**：`(引导模块源码 ＋ 模式 ＋ 指令集版本)` → Pyawa 编译器 →
  产物入库。**禁止**在运行时首次编译后缓存进冻结表——那会让构建不确定（`BC-16`）。
- **IM-34** 冻结产物的**指令集版本必须**与运行时的 `BC-40` 常量一致；
  不一致时**必须**回退到**从源码重新编译**，而**不是**报错——否则升指令集后无法启动。
