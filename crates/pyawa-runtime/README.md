# pyawa-runtime

**真实机器**的能力实现 ＋ 独立运行时入口。

## 为什么它必须是一个独立 crate

`docs/DESIGN.md` §7 原则 5 要求 **VM 核心不得依赖 `std::fs`／`std::net`／libc、
不得出现 `#[cfg(target_os)]`**。这条要靠 CI 强制（`tests/ci/`），而它只有在
"平台依赖被集中在一个 crate 里"时才是可检查的。本 crate 就是那个集中点：

```
pyawa-core（无平台依赖）──► pyawa-capabilities（只有接口形状）
                                      ▲
                                      │ 实现
                            pyawa-runtime（真实机器）
```

## 它提供的是什么

- **同一套能力接口的真实机器实现**——`DESIGN.md` §7：独立运行时**自动注入**它，
  于是"纯 Python 程序都能跑"在独立运行时下**无条件成立**；嵌入时则只在
  **宿主已实现的域内**成立（`DESIGN.md` §7、§2）
- 独立运行时入口：执行文件／字符串／字节码，REPL、`-c`、stdin
- **不是**沙箱的反面：受限 provider 是同一接口的另一实现，两者写法不变（`DESIGN.md` §12 M5）

## 硬约束

| 约束 | 来源 |
|---|---|
| 与宿主 provider 是**同一接口**的两种实现，不得引入新句柄类型或新编程写法 | `DESIGN.md` §2 |
| **未实现**（接口槽位不存在）与**已实现但拒绝**（真实机器错误）必须分清，禁止混用 | `DESIGN.md` §2 |
| 阻塞式能力调用必须走独立线程 ＋ 取消令牌，且**只传裸数据／OS 句柄** | `DESIGN.md` §7.2、§3 不变量 4 |
| VM 线程等待能力结果必须用**可取消的等待**，不能无限阻塞 | `DESIGN.md` §7.2 |
| cwd 是实例状态，必须与根能力一起定义；绝对路径 ＝ chroot 语义 | `DESIGN.md` §7.4 |

`DESIGN.md` §13-13 未决：`-c`／stdin／`compile()` 的默认模式，
以及**嵌入执行接口必须显式声明模式**（宿主必须表态、无默认）。

## 状态

**占位 crate**：只有骨架。能力接口形状待 `docs/SPEC-capabilities.md` 写出后接线。
